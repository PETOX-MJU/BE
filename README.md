## 제안 배경

틱톡·유튜브 숏츠·인스타그램 릴스 시청 시간이 늘면서, 스스로 그만두기 어려운 숏폼 중독이 청소년부터 중장년층까지 폭넓게 나타나고 있습니다. 저희 팀도 자기 전 잠깐 보려다 한두 시간을 흘려보내고, 늦게 잠들어 다음 날 집중력이 떨어지는 경험을 반복하며 이 문제를 체감했습니다.

기존 대응 방식은 두 가지로 나뉘지만 모두 한계가 있습니다.

- **차단형** (iOS 스크린 타임, Android 디지털 웰빙): 사용자가 언제든 스스로 해제할 수 있어 실질적인 강제력이 없고, 우회 방법도 널리 공유되어 있습니다.
- **통계 제시형**: 사용 시간을 리포트로 보여줄 뿐, 사용 시간을 줄여야 할 이유는 만들어주지 못합니다.

두 방식 모두 절제에 대한 보상이 없어 사용자는 며칠 안에 원래 패턴으로 되돌아갑니다. 즉, 기존 서비스는 '막는 것'에 집중할 뿐 '스스로 멈추고 싶게 만드는 것'에는 접근하지 못하고 있습니다.

## 핵심 아이디어

펫톡스는 사용자가 설정한 시간대에 숏폼 앱을 실행하면, 미리 등록해 둔 동물 캐릭터가 화면 위에 나타나 영상을 가리는 서비스입니다. 앱을 강제로 종료시키는 것이 아니라 캐릭터가 시야를 가려 '잠깐 멈추는 순간'을 만들어, 사용자가 스스로 화면에서 벗어나도록 유도합니다.

**차단이 아닌 개입, 통제가 아닌 유도**가 펫톡스의 출발점입니다.

## 동작 방식

1. **초기 설정**: 최초 실행 시 하루 목표 시간과 숏폼 방지 시간대를 정하고 함께할 캐릭터를 고릅니다. 기본 캐릭터(골든 리트리버·닥스훈트·코기·허스키) 중 하나를 고르거나, 반려동물 사진을 찍으면 그 털색을 입힌 픽셀 캐릭터가 만들어집니다.
2. **개입 트리거**: 유튜브 쇼츠·인스타그램 릴스·틱톡 화면을 1분 넘게 보면 캐릭터가 화면 밖에서 걸어 들어와 영상을 가립니다. 온디바이스 숏폼 분류기가 화면을 판별해서, 유튜브 홈이나 일반 영상에서는 나오지 않습니다.
3. **단계적 강화**: 처음에는 캐릭터가 작게 등장하지만, 시청이 계속될수록 30초마다 커져 화면을 더 많이 가리고 진동도 울립니다.
4. **매일 미션**: 매일 자정이 지나면 두 가지 미션이 새로 생깁니다.
   - `숏폼 {목표}분 이내로 보기` — 그날 본 숏폼 시간의 합계가 목표 시간 이하
   - `오늘 펫 N회 이하로 보기` — 캐릭터가 나타난 횟수가 목표 이하 (어제보다 1회 적게, 최소 2회)
5. **보상**: 미션을 지키면 다음 날 자정에 각 20코인, 출석하면 5코인(7일 연속 시 +30)이 들어옵니다. 코인으로 방 테마와 가구를 사서 캐릭터의 공간을 꾸미고, 펫 슬롯을 늘려 새 친구를 데려올 수 있습니다. 참는 행위가 손실이 아니라 눈에 보이는 보상으로 돌아오면서, 한 번의 절제가 다음 절제로 이어집니다.

## 기존 방식과의 차별성

1. **강제 차단이 아닌 자발적 중단** — 캐릭터에 대한 애착을 이용해 사용자가 스스로 앱에서 벗어나도록 돕습니다.
2. **나만의 캐릭터** — 기본 캐릭터뿐 아니라, 반려동물 사진의 털색을 입힌 픽셀 캐릭터로 '남의 캐릭터'가 아닌 '나의 반려동물'로 친숙함과 유대감을 높입니다.
3. **보상이 있는 절제** — 숏폼을 참은 만큼 코인과 꾸미기로 돌아와, 통계 제시형 서비스가 주지 못한 '줄여야 할 이유'를 제공합니다.

## 기대 효과

**사회적 효과**: 강제 차단 대신 캐릭터와의 유대감으로 스스로 화면에서 벗어나도록 유도하기 때문에, 차단형 앱에 거부감을 느끼던 사용자도 부담 없이 시작할 수 있습니다. 자발적 중단이 반복되면 자극적인 콘텐츠에 계속 노출되던 뇌에 휴식 시간이 생기고, 알고리즘에 이끌려 흘려보내던 시간을 아낄 수 있습니다.

**일상생활 개선**: 자기 전 무심코 이어지던 시청이 줄어들면서 잠드는 시간이 앞당겨지고 수면의 질이 회복됩니다. 학습·업무 중 습관적으로 휴대폰을 보는 횟수가 줄어 집중력을 되찾고, 절제한 시간이 캐릭터의 성장이라는 눈에 보이는 결과로 쌓이면서 지속적인 사용 습관 변화로 이어질 수 있습니다.

## 아키텍처 — BE

### 전체 그림

```
React Native 앱 (Android)
  │ ① Supabase Auth SDK로 로그인·회원가입 (이메일, 카카오)
  │ ② supabase-js로 본인 데이터 직접 읽기·쓰기 — RLS가 본인 행만 허용
  │ ③ 코인이 걸린 일은 RPC(서버 함수)로만
  ↓ HTTPS (JWT)
Supabase
  ├ Auth            JWT 발급, 가입 시 profiles 자동 생성 (트리거)
  ├ PostgreSQL+RLS  profiles, pets, items, user_items, coin_ledger, missions, daily_usage …
  ├ RPC             check_in · buy_item · coin_balance · complete_mission · report_pet_calls
  ├ pg_cron         00:10 오늘 미션 생성, 00:05 어제 미션 정산·코인 지급
  └ Edge Function   delete-account (회원 탈퇴)
```

앱은 Supabase를 직접 호출합니다. FastAPI(`app/`)는 초기에 JWT 검증과 주간 리포트를 맡았지만, 주간 분석이 폰으로 옮겨가면서(ADR-37) 앱이 호출하지 않게 되어 EC2 서버를 정지했습니다(ADR-38). 코드는 기록으로 남겨 두었습니다.

### 신뢰 경계 — 코인은 클라이언트가 만들 수 없다 (ADR-004)

- 잔액 칸이 따로 없습니다. **코인 원장(`coin_ledger`)의 합계가 잔액**이고, 앱은 원장을 읽기만 할 수 있습니다(쓰기 RLS 정책 없음).
- 코인이 움직이는 경로는 `security definer` 함수뿐입니다. 모든 함수는 사용자 id를 인자로 받지 않고 로그인 토큰(`auth.uid()`)으로 대상을 정합니다.

| 함수 | 역할 | 신뢰 장치 |
|---|---|---|
| `check_in()` | 출석 +5 (7일 연속 +30) | 날짜를 서버가 KST로 계산, `사용자+날짜`로 고정한 멱등키 |
| `buy_item(p_item_id, p_request_id)` | 구매 → 코인 차감 + 아이템·펫 슬롯 지급 | 잔액 확인과 차감을 한 트랜잭션에서, 중복 구매·테마 순서 규칙을 서버에서 강제 |
| `settle_missions()` (cron) | 어제 미션 판정 → 성공이면 +20 | 미션 id로 고정한 멱등키, `in_progress`일 때만 바꾸는 조건부 업데이트 |
| `complete_mission(...)` | 미션 보상 직접 받기 | 날짜가 지나야만 판정, 자동 정산과 겹쳐도 한 번만 지급 |

- 펫 레벨·애착도·슬롯 수·펫 호출 수처럼 조작되면 안 되는 칸은 **컬럼 단위 권한**으로 앱이 직접 바꾸지 못합니다(ADR-22).

### 멱등성과 동시성 (ADR-008)

`request_id` unique 제약은 같은 요청의 재시도만 막습니다. request_id가 다른 두 요청이 동시에 들어오면 막지 못합니다 — 동시성 테스트(`tests/test_rpc_trust.py`)에서 잔액 100에 60짜리 두 건이 둘 다 통과해 잔액이 -20이 되는 걸 재현했습니다.

그래서 코인 함수는 진입 직후 **사용자 단위 advisory lock**(`pg_advisory_xact_lock(hashtextextended(auth.uid()::text, 0))`)을 겁니다. 같은 사용자의 요청만 줄 세우고 다른 사용자는 막지 않으며, 트랜잭션이 끝나면 자동으로 풀립니다. 펫 추가 한도 검사(`enforce_pet_slot_limit`)도 같은 잠금을 써서, 버튼을 연타해도 한도를 넘는 펫이 생기지 않습니다.

### 미션 — 측정은 폰, 판정은 서버 (ADR-39·40·41)

```
[폰 오버레이]  숏폼 화면(분류기 판정)을 본 1초마다 +1, 펫이 처음 나타날 때마다 +1 → 기기에 날짜별로 저장
      │  앱을 켤 때 최근 7일치 업로드 (오버레이가 돈 날만)
      ↓
[Supabase]
  daily_usage       앱별 숏폼 시청 분 (upsert, 같은 날 값은 줄지 않음)
  report_pet_calls  펫 등장 횟수 (하루 누적값 덮어쓰기, 범위 밖 날짜는 무시)
      │
  00:10 generate_daily_missions()   사용자마다 "숏폼 {goal_minutes}분 이내", "펫 N회 이하"
  00:05 settle_missions()           어제 미션 판정 → coin_ledger에 +20
```

- 화면 캡처와 원본 영상은 폰 밖으로 나가지 않습니다. 서버에는 **하루 합계 숫자**만 올라옵니다.
- 그날 업로드가 한 줄도 없으면 판정 근거가 없으므로 실패로 처리합니다.
