# 펫톡스(peTox) 프로젝트 마일스톤 문서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 펫톡스 (peTox) |
| 목표 | Android 기반 숏폼 앱 사용 시간 제어 솔루션 |
| 최종 제출일 | 2026-10-01 |
| 시작일 | 2026-09-04 |
| 총 기간 | 4주 (28일) |
| PM/Design | 최수빈 |
| Backend | 김민형 |
| Frontend | 박민규 |
| AI/ML | 박현식 |

## 2. 기술 스택

### 아키텍처
- **Frontend**: React Native (Android 전용)
- **Backend**: FastAPI + SQLAlchemy
- **Database**: Supabase (PostgreSQL + Auth)
- **Image Processing**: ML Kit Subject Segmentation (On-device)
- **Overlay**: SYSTEM_ALERT_WINDOW + AccessibilityService

### 현재 완성도
- ✅ DB 스키마 (11개 테이블)
- ✅ FastAPI 초기 세팅 (/health, /db-health, /items, /auth/signup)
- ✅ Supabase 연동

## 3. 현황 요약

### 완료된 작업
1. **Backend 기초 구축 (완료)**
   - FastAPI 애플리케이션 초기화
   - Supabase 클라이언트 연동
   - DB 스키마 설계 및 생성 (테이블 11개)
   - 기본 엔드포인트 구현 (health check, DB 상태, auth)

2. **데이터베이스 설계 (완료)**
   - profiles, pets, logs 테이블 등 핵심 스키마
   - 인증 및 사용자 관리 구조 설계

### 진행 예정 작업
1. **Week 1**: React Native 앱 초기 세팅 및 안드로이드 네이티브 통합
2. **Week 2**: UsageStatsManager, AccessibilityService 구현 및 오버레이 기능
3. **Week 3**: ML Kit 픽셀 캐릭터 변환, 캐릭터 성장/코인/상점 기능
4. **Week 4**: 리포트, 온보딩, 설정 화면, QA 및 최종 제출

## 4. Phase별 마일스톤

### Phase 1: React Native & Android 기초 구축
**기간**: 2026-09-04 ~ 2026-09-10 (7일)

#### 목표
- React Native 프로젝트 초기 세팅 완료
- Android 네이티브 모듈 기본 구조 구현
- 백엔드와의 기본 통신 연결

#### 담당자
- **FE (박민규)**: React Native 프로젝트 초기화, 화면 구조 설계
- **BE (김민형)**: 인증, 사용자 프로필 엔드포인트 완성
- **PM (최수빈)**: 온보딩/메인 화면 디자인 1차 검수

#### 산출물
1. React Native 프로젝트 저장소 설정 완료
2. Android 네이티브 모듈 보일러플레이트 (UsageStatsManager, AccessibilityService)

### Phase 2: 사용 시간 감지 & 오버레이 기능
**기간**: 2026-09-11 ~ 2026-09-17 (7일)

#### 목표
- UsageStatsManager를 통한 숏폼 앱 사용 시간 감지
- SYSTEM_ALERT_WINDOW를 이용한 오버레이 캐릭터 표시
- 백그라운드 서비스 안정성 확보

#### 담당자
- **FE (박민규)**: AccessibilityService 구현, 오버레이 UI 개발
- **BE (김민형)**: `/logs` (사용시간 기록) 엔드포인트 개발
- **AI/ML (박현식)**: ML Kit 환경 셋업 시작

#### 산출물
1. UsageStatsManager 네이티브 모듈 (Python 래퍼 포함)
2. AccessibilityService 백그라운드 서비스 구현
3. 오버레이 캐릭터 기본 렌더링
4. `/logs` POST/GET 엔드포인트

#### 위험요인
- Android 12+ 권한 제한 (QUERY_ALL_PACKAGES)
- 배터리 소비 최적화 필요
- 오버레이 성능 문제

#### 성공 기준
- 특정 앱(예: Instagram) 사용 시간 추적 확인
- 오버레이가 안정적으로 표시/숨김 전환
- 10초 이상 백그라운드 동작 확인

- **FE (박민규)**: 캐릭터 갤러리, 성장 애니메이션, 상점 UI

#### 산출물
1. ML Kit 기반 이미지 분할 및 픽셀화 모듈
2. 캐릭터 성장 단계 데이터 모델 (DB 저장)

#### 위험요인

- 픽셀화 품질 보장

## 8. 부록: 기술 부채 및 향후 개선 사항

### Phase 1~4에 포함되지 않은 항목 (Post-MVP)
1. 알림 시스템 (FCM, 로컬 알림)
2. 소셜 기능 (친구 추가, 순위)
3. 클라우드 백업 (사진, 캐릭터 데이터)
4. iOS 지원 (범위 외)
5. 고급 분석 (ML 기반 사용 패턴 분석)

### 성능 최적화 (최소한 Week 3~4에 반영)
- 캐시 전략 (Redis 고려)
- 이미지 리사이징 및 압축
- 쿼리 최적화 (인덱스, N+1 해결)
- 번들 크기 최적화
