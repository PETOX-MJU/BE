## 1. 소개 (Introduction)

### 1.1 목적
본 문서는 peTox 프로젝트의 소프트웨어 요구사항을 명세한다. peTox는 스마트폰 과다 사용을 방지하기 위한 Android 애플리케이션으로, 사용자의 숏폼 콘텐츠(틱톡, 인스타그램 릴스, 유튜브 쇼츠) 사용시간을 모니터링하고 캐릭터 기반의 게이미피케이션을 통해 점진적인 사용시간 감소를 유도한다.

### 1.2 범위
**포함 대상**:
- 사용시간 감지 및 로깅 시스템
- 사용자 인증 및 프로필 관리 (Supabase Auth)
- 캐릭터 성장 및 상호작용 시스템
- 오버레이 화면 표시 및 햅틱 피드백
- 일일/주간 미션 및 보상 시스템
- 통계 리포트 (앱별/일별/주간 비교)
- 상점 및 아이템 구매 시스템
- FastAPI 백엔드 및 Supabase 데이터베이스

**제외 대상**:
- iOS 플랫폼 지원
- 생성형 AI를 활용한 콘텐츠 생성 (ML Kit Subject Segmentation만 온디바이스 사용)
- 실시간 음성/영상 통신

## 2. 전반적 설명 (Overall Description)

### 2.1 제품 관점

#### 2.1.1 시스템 아키텍처
```
[Android App] <--> [FastAPI Backend] <--> [Supabase (PostgreSQL + Auth)]
                          |
                    [Usage Monitoring]
                    [Character Management]
                    [Mission/Report Logic]
```

#### 2.1.2 주요 구성요소
1. **Android 클라이언트**: React Native 기반 UI, 사용시간 감지, 오버레이 표시
2. **Backend API**: FastAPI로 구현된 REST API 서버
3. **Database**: Supabase (PostgreSQL 기반)
4. **인증**: Supabase Auth (이메일 + 비밀번호)

### 2.2 제품 기능 개요

#### 2.2.1 온보딩
- 사용자 목표 사용시간, 집중시간대, 취침시간 설정
- 기본 캐릭터 또는 반려동물 사진 등록 후 픽셀 변환
- 권한 안내 (UsageStatsManager, AccessibilityService, SYSTEM_ALERT_WINDOW, 알림)

#### 2.2.2 홈 화면
- 오늘 사용시간 및 목표 대비 진행률 대시보드
- 캐릭터 상태 표시 (레벨, 애착도, 이미지)
- AI 추천 일일 미션 표시

#### 2.2.3 오버레이 시스템
- 설정 시간대/목표 초과 시 캐릭터 등장
- 시청 지속 시 단계적 크기 확대 (초기→중간→최대)
- 햅틱 피드백 (진동 강도 점진적 증가)

#### 2.2.4 캐릭터 관리
- 성장 단계 및 애착도 확인
- 코인으로 옷 구매/펫 슬롯 확장
- 사진 재등록 및 픽셀 변환

#### 2.2.5 리포트 화면
- 앱별 사용시간 통계 (차트 또는 테이블)
- 일별 사용시간 변화
- 전주 대비 변화율 (긍정적 문구: "낭비되는 시간을 아꼈어요")
- 미션 완료 히스토리

#### 2.2.6 상점
- 의류, 펫 슬롯 확장 아이템 판매
- 보유 아이템함 표시
- 코인으로 구매

#### 2.2.7 설정
- 목표 사용시간 수정
- 감지 앱 관리 (틱톡/릴스/쇼츠 on/off)
- 권한 관리
- 알림 설정 (미션, 리포트)
- 계정 관리 (로그인/로그아웃/데이터 초기화)

#### 2.2.8 하단 네비게이션
- 홈 (캐릭터 탭)
- 마이페이지
- 리포트
- 상점

### 2.3 사용자 특성

#### 2.3.1 사용자 페르소나
1. **MZ 세대 (10~20대)**: 숏폼 콘텐츠에 높은 중독성을 가진 집단
2. **부모/보호자**: 자녀의 스마트폰 사용시간 제어 의도
3. **자율 조절 시도자**: 스스로 사용습관 개선을 원하는 사용자

#### 2.3.2 사용자 기술 수준
- Android 스마트폰 기본 조작 가능
- 앱 설치/권한 허용 이해 가능
- 평균적인 스마트폰 리터러시 수준

### 2.4 제약사항

#### 2.4.1 기술 제약
- **플랫폼**: Android 전용 (iOS 미지원)
- **최소 OS 버전**: Android 8.0 이상 (UsageStatsManager 사용)
- **네트워크**: 인터넷 연결 필수 (클라우드 동기화)
- **권한**: 접근성 서비스, 사용량 통계 접근, 오버레이 권한 필수

#### 2.4.2 데이터 제약
- Supabase 데이터베이스 크기 제한
- Row-Level Security (RLS) 정책으로 개인데이터 보호
- 로그 데이터 보관 기간 정책 필요

#### 2.4.3 일정 제약
- **최종 제출일**: 2026-10-01 (약 4주)
- **경진대회 일정**: MJU 주최 대회 일정 준수

### 2.5 가정사항과 종속성

#### 2.5.1 가정사항
1. 사용자는 유효한 이메일 주소로 회원가입 가능
2. 반려동물 사진은 명확한 주체 구분이 가능한 형식 (JPG, PNG)
3. 사용자가 필요한 권한을 모두 허용함 (차단 시 기능 제한)
4. 네트워크 환경이 안정적임 (주기적 동기화 가정)

#### 2.5.2 종속성
1. **Supabase**: 클라우드 데이터베이스 및 인증 서비스
2. **FastAPI**: 백엔드 API 서버 (AWS 배포 예정)
3. **Google ML Kit**: 온디바이스 픽셀 변환 (외부 API 미사용)
4. **React Native**: 크로스플랫폼 모바일 프레임워크

## 4. 외부 인터페이스 요구사항 (External Interface Requirements)

### 4.1 사용자 인터페이스 (UI)

#### 4.1.1 화면 목록
1. **스플래시 화면**: 앱 로드 시 표시 (2초)
2. **로그인/회원가입 화면**: 이메일/비밀번호 입력
3. **온보딩 화면**: 목표, 캐릭터, 권한 설정 (다단계)
4. **홈 화면**: 대시보드, 캐릭터, 미션, 오버레이
5. **캐릭터 화면**: 캐릭터 상세 정보, 의류 장착
6. **리포트 화면**: 통계, 차트, 미션 히스토리
7. **상점 화면**: 아이템 목록, 보유 아이템함
8. **설정 화면**: 목표, 감지 앱, 권한, 알림, 계정
9. **마이페이지 화면**: 사용자 정보, 캐릭터 갤러리, 요약 통계
10. **오버레이 화면**: 팝업 캐릭터 (다른 앱 위에 표시)

#### 4.1.2 UI 설계 원칙
- **일관성**: 모든 화면에서 동일한 디자인 시스템
- **직관성**: 사용자 학습 곡선 최소화
- **반응성**: 터치 반응 < 100ms
- **어두운 모드**: 시스템 설정에 따른 자동 적용

### 4.2 하드웨어 인터페이스

#### 4.2.1 Android 시스템 인터페이스
- **UsageStatsManager**: 사용시간 데이터 획득
- **AccessibilityService**: 포그라운드 앱 감지
- **SYSTEM_ALERT_WINDOW**: 오버레이 표시
- **NotificationManager**: 푸시 알림 발송
- **Vibrator**: 햅틱 피드백
- **SharedPreferences/DataStore**: 로컬 설정 저장

### 4.3 소프트웨어 인터페이스

#### 4.3.1 Supabase API
- **Authentication**: `auth.sign_up()`, `auth.sign_in()`, `auth.sign_out()`
- **Database**: SELECT, INSERT, UPDATE, DELETE (via Supabase Client)
- **Storage**: 사진 업로드/다운로드 (향후 확장)
- **Realtime**: 실시간 데이터 동기화 (선택사항)

#### 4.3.2 FastAPI 백엔드 API
주요 엔드포인트:
```
POST   /auth/signup
POST   /auth/login
POST   /auth/logout
GET    /profiles/{user_id}
PUT    /profiles/{user_id}
GET    /pets/{user_id}
POST   /pets/{user_id}
GET    /usage-logs/{user_id}?date=YYYY-MM-DD
GET    /usage-stats/{user_id}?period=week|month
POST   /missions/assign
GET    /missions/{user_id}
PUT    /missions/{mission_id}
GET    /reports/{user_id}?period=week|month
GET    /items
POST   /items/purchase
GET    /users/{user_id}/items
```

#### 4.3.3 Google ML Kit API
- **Subject Segmentation**: 사진에서 주체 추출 (온디바이스)

### 4.4 통신 프로토콜

- **프로토콜**: HTTPS (TLS 1.2 이상)
- **데이터 형식**: JSON
- **인증**: Bearer Token (JWT)
- **타임아웃**: 요청 타임아웃 30초

## 5. 데이터 요구사항 (Data Requirements)

### 5.1 데이터 구조
모든 데이터는 Supabase PostgreSQL에 저장되며, 주요 테이블:
- **profiles**: 사용자 프로필 (목표 시간, 시간대 설정)
- **pets**: 캐릭터 정보 (이미지, 레벨, 애착도)
- **usage_logs**: 앱 사용 시간 로그
- **missions**: 미션 정의
- **user_missions**: 사용자별 미션 진행 상태
- **items**: 상점 아이템 정보
- **user_items**: 사용자 보유 아이템
- **coin_ledger**: 코인 거래 이력
- **detected_apps**: 감지 대상 앱 정보

### 5.2 데이터 보안
- **암호화**: 저장 데이터 암호화 (Supabase 표준)
- **접근 제어**: Row-Level Security (RLS) 정책
- **감사**: 중요 작업 로깅

### 5.3 데이터 보관 정책
- **활성 데이터**: 무제한 보관
- **로그 데이터**: 30일 후 아카이빙 또는 삭제 (설정 가능)
- **삭제된 계정**: 30일 후 전체 삭제
